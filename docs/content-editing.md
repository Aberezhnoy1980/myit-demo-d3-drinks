# N9 — мастерская содержания

Реализовано 05.11.2026. Это локальная форма без backend продукта и доступа на запись. Она загружает текущий файл, показывает изолированный предпросмотр и выдаёт один JSON с текстами и подготовленными PNG. Публичная страница редактор не содержит.

## Инструкция владельцу

1. Запустите preview по README и откройте http://127.0.0.1:4333/__editor__/.
2. Измените заголовок или описание. Выберите один из трёх вкусов, исправьте его описание, характер и демонстрационный состав. Названия вкусов остаются фиксированными.
3. При необходимости выберите PNG/JPEG/WebP с компьютера. Меняется **вся иллюстрация банки**, не надпись на этикетке. Укажите понятное описание картинки для незрячих посетителей. Кнопка «Вернуть авторскую упаковку» возвращает исходный SVG выбранного вкуса.
4. Нажмите «Обновить предпросмотр». Проверьте 390 и 1440 px, все вкусы, движение/паузу ленты и «Где купить». Широкий предпросмотр прокручивается внутри своей области.
5. Нажмите «Подготовить экспорт» → «Скачать polden-content.json». Убедитесь, что файл сохранён. Альтернатива — раскрыть «Содержимое экспортируемого файла» и сохранить его целиком как UTF-8 JSON.
6. Откройте терминал в папке проекта. Замените путь в кавычках на путь к сохранённому файлу:

```sh
fnm exec --using=v22.23.4 -- node tools/apply-content.mjs "/полный/путь/polden-content.json"
fnm exec --using=v22.23.4 -- node tools/build.mjs
```

7. Обновите локальную страницу. Применение и сборка повторно проверяют данные. Ошибка выводится текстом; невалидные данные не заменяют рабочую сборку. Команды ничего не публикуют.

Закрытие вкладки теряет несохранённый черновик. Автосохранения нет; при незавершённых изменениях запрашивается подтверждение выхода. Сообщение о скачивании означает запрос браузеру, а не подтверждение наличия файла на диске.

## Ограничения

| Поле | Допустимо |
|---|---|
| Заголовок: первая строка / начало второй / курсив | 1–12 / 1–8 / 1–14 символов |
| Две строки описания первого экрана | Каждая 1–58 символов |
| Описание вкуса / характер / состав | 1–240 / 1–60 / 1–300 символов |
| Описание изображения | 8–180 символов |
| Исходная картинка | PNG, JPEG, WebP; до 4 МБ и 20 мегапикселей |
| Подготовленная картинка | PNG RGB/RGBA 8 бит, до 320×620 и 200 КБ; пропорции исходника сохранены с прозрачными полями |
| Файл содержания | JSON версии 1, до 850 КБ; точный набор обязательных полей |

Пустые/неполные данные, HTML, управляющие символы, переводы строк, внешние URL изображений и пользовательский SVG отклоняются. PNG проверяется по структуре, контрольным суммам и распакованным пикселям. При большом весе редактор дополнительно уменьшает растр; если лимит недостижим, возвращает ошибку. Максимальные непрерывные строки переносятся и не создают горизонтальную прокрутку.

Нельзя добавлять вкусы/разделы, менять макет, магазины, ссылки или пользователей. Составы — демонстрация, не проверенная рецептура. После изменения содержания требуется визуальная проверка: ограничение длины не заменяет редактуру.

## Откат

Перед применением предыдущий `content/site.json` сохраняется в `content/backups/<sha256>.json`; путь печатается командой. Передайте его той же команде apply-content, затем повторите build. Возврат к исходным текстам и упаковке:

```sh
fnm exec --using=v22.23.4 -- node tools/apply-content.mjs content/original.json
fnm exec --using=v22.23.4 -- node tools/build.mjs
```

Сохранён `docs/evidence/r2/editor-export.json`. Затем выполнены apply-content и build, проверен фактический рендер и два цикла ленты на 390 px. Исходное содержание восстановлено; добавленный PNG исчез из dist.

Результаты: `n9-before-build.json`, `n9-edited-build.json`, `n9-rollback.json`. Тексты и исходные активы восстановились побайтно. В ходе опыта отдельно добавлен перенос длинных строк в CSS, поэтому CSS отличается от начального снимка опыта; это явно отмечено в rollback. Автоматический тест 22 повторяет полный цикл в отдельной копии без промежуточных изменений кода и проверяет полное совпадение файлов сборки после отката.

В UI отдельно проверены пустой заголовок, неполный импорт, повреждённый PNG, предельные непрерывные тексты на 390/1440. Ошибки сохранили предыдущие данные. Негативные случаи, проверяемые только Node, перечислены в тестах и acceptance. Это авторская проверка, не независимая приёмка N9.
